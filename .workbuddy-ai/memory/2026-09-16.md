### 关键新洞察（值得记住）

- **最精确的差异**：pi 的 context projection 是**固定 5 步算法**（扩展点窄且显式：entryProjectors / transform_context / hooks）；dsh 的 **`system-prompt/assemble` 本身就是一个 waterfall 事件**，插件可包裹整个 assembly。两者是**两种可靠性策略**，不是先进/落后。
- **两边的独立共识**：① prompt 应作为"从事实投影出来的派生消息"而非请求字段（pi §4.2 / dsh system/message surface node）；② **中间插入会摧毁 provider KV cache** —— pi 用 append-only context invariant，dsh 用 cache-safe PromptContext 快照。同一个约束的两种工程表达。
